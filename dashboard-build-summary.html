Budget Analytics

/budget
Built

The deepest surface. Budget vs actual with a predictive twist.

  • Approved / YTD / encumbrances / remaining KPIs with year-over-year deltas
  • Fiscal-year selector and fund segmented control
  • Year-End Projection (burn-rate + pacing) with over-budget rows flagged
  • Top Movers, category drill-down, revenue vs expenditure, open commitments, amendments log
  • CSV export and a print path; entry to the Council Report

  • Searchable AG Grid vendor directory with flag and anchor status

Council Financial Report

/report
Built

The Finance Director's most common real-world task: the monthly report to Council, as a printable, document-style PDF with an executive summary, budget vs actual, fund balance, variance highlights, and an on-chain verification trail.

Records, admin, and public (built this session)

Contracts

/contracts
Built

Resolves the long-standing department-vs-contract confusion: the contract becomes the real procurement object. A register with a balanced "Needs Attention" view (over/near ceiling, expiring, PO breach, stalled), drilling into a per-contract verifiable record at /contracts/[id] with a not-to-exceed burn meter and a payment trail carrying on-chain proof.

Administration

/admin
Built

A tabbed console for the Finance Director wearing the tenant-admin hat: Governance (close-of-period sign-off, anchor history, override audit trail), Users & Roles (RBAC per the Access Control Policy), Data Connections (Plaid / RePay / ERP feed health), and Settings & Ruleset (the MCC-to-category semantic layer).

Public Transparency Portal

/public
Built

A full-bleed, citizen-facing page: a plain-language budget summary plus an "open checkbook" that lets the public search every vendor payment, the dominant real-world public query, with a verified badge per row and CSV download.

How it came together

The build order, each step verified by a green type/build gate and a live preview check.

  1. Three analytics pages.

    Budget Analytics, Vendor Intelligence, and Department Analysis, mock-first and wired through the existing useMock fallback.

  2. Budget roadmap enhancements.

    Burn-rate forecast and pacing, fiscal-year selector, year-over-year, category drill-down, CSV/print export, open commitments, and revenue vs expenditure.

  3. Council Financial Report.

    A printable record built around the Finance Director's monthly deliverable, reusing the budget data and the on-chain verification theme.

  4. Public open checkbook.

    Added a searchable public payment register to the citizen portal, matching how real open-checkbook sites are actually used.

  5. Slim-down and Overview reorder.

    A deep review removed redundant variance views and reordered the Overview to lead with budget and variance, the power user's real first question.

  6. Contracts.

    A register plus a per-contract verifiable record, making the contract the real procurement object.

  7. Administration.

    The final tabbed console, completing all five formerly-deferred features.

Architecture & decisions

Consistent patterns across every surface, so the demo stays coherent and a real backend can slot in later.

DecisionWhat it means
Mock-firstEvery page renders from fixtures and only calls a backend if NEXT_PUBLIC_API_URL is set. The demo runs with no server.
useMock fallbackEach new data function mirrors the existing pattern, so real endpoints replace mock data with no UI rewrite.
Existing design kitNo new colors or fonts. Reused the Civic-Chain tokens, components, and the no-em-dash voice throughout.
Shared logicScoring lives in pure modules (budget-health.ts, contracts.ts) so pages that show the same signal never drift.
On-chain themeVerification proof (fingerprint, ledger tx, anchor) surfaces on the ledger, contracts, the report, and Administration governance.
No backend changesNo DB, validator, or contract edits. The real governance backend is untouched and still powers live signing in the Ledger drawer.
